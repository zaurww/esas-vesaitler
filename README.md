# Əsas Vəsaitlər

Учёт основных средств и расчёт амортизации **для налоговых целей** по
законодательству Азербайджана — ст. 114 и 115 Налогового кодекса.

Локальное приложение: Python-движок и веб-интерфейс на `localhost`. Без
сервера, без облака, без учётных записей. Данные лежат у вас на диске
обычным текстом.

**Статус: `0.9.0`, этап 1 завершён.** Не `1.0` намеренно — см. «Чего ещё нет».

---

## Запуск

Двойной клик по **`Başlat.bat`**. Откроется окно консоли — оно и есть
программа; закрыли окно, остановили приложение. Браузер откроется сам на
<http://127.0.0.1:8777/>.

Нужен Python 3.11+ и одна библиотека — для чтения и записи `.xlsx`:

```
python -m pip install -r requirements.txt
```

Из командной строки:

```
python ev.py                       запустить интерфейс
python ev.py calc <клиент> <год>   отчёт в консоль
python ev.py export <клиент> <год> выгрузка .xlsx
python ev.py close <клиент> <год>  закрыть год
python ev.py verify <клиент>       пересчитать закрытые годы и сверить
python ev.py test                  прогнать контрольные примеры движка
```

`verify` и `test` — разные вещи: первая сверяет **эту установку** (пересчитывает
закрытые годы клиента и сравнивает с сохранёнными остатками), вторая проверяет
**сам движок** и работает без данных клиентов.

## Как это устроено

**Данные — это события. Результаты — вычисляются.**

Пользователь вводит только факты: поступление, выбытие, ремонт,
дооборудование, статус предпринимателя, выбранную ставку, решение о
списании. Амортизация, остаточная стоимость, накопленная, лимит ремонта,
входное сальдо следующего года — производные величины, они пересчитываются
из событий при каждом запуске и нигде не хранятся.

Отсюда главное свойство: исправление в движке распространяется на все
открытые годы сразу, миграций цифр не бывает, а по журналу событий видно,
как получена любая цифра.

```
clients/<клиент>/*.tsv   факты          ← единственный источник истины
        ↓
engine/                  расчёт          ← stateless, состояния не держит
        ↓
web/ + Excel             отчёты          ← ничего не хранят
```

Расчёт года (`engine/calc.py`):

```
1. остаток на начало        ← явная строка ∨ остаток прошлого года ∨ 0
2. + поступления года       полная годовая норма, без пропорции
2a.+ дооборудование         компонент к существующему ОС, без лимита
3. + капитализированный ремонт   превышение лимита ст. 115
4. − остаток выбывших
   = база
5. тест 500/5%
6. × применённая ставка
7. = остаток на конец       → входное сальдо следующего года
```

Ставка — три независимых множителя, и отчёт печатает это разложение:

```
норма ст.114.3 × коэффициент статуса = потолок ≥ применённая ставка
```

Коэффициент микро (×2) и малого (×1,5) — **право, а не обязанность**
(114.3-1, 114.3-2), поэтому сам по себе не применяется: без явного выбора
берётся обычная норма.

## Что защищает от ошибки

Расчёт уходит в декларацию без ручной проверки, поэтому:

- **расчёт либо даёт результат, либо падает** — никакого молчаливого нуля.
  Правило выведено из провала исходной книги Excel, где `IFERROR` съедал
  `#VALUE!` и все 62 объекта показывали нулевую амортизацию при остатке
  120 680 AZN;
- **каждая запись:** бэкап → запись → перечитать хранилище → пересчитать все
  открытые годы → откат при любой ошибке. Проверки полей по отдельности не
  ловят ни удаление объекта, на который ссылается сальдо, ни ставку 90%,
  которая записывается чисто и ломает каждый отчёт после;
- **три контроля в движке**, срыв любого останавливает расчёт: тождество
  баланса по категориям, сходимость движения (первоначальная − накопленная =
  остаточная), потолок ставки;
- **`ev.py verify`** пересчитывает закрытые годы и сверяет с сохранёнными
  снимками — детектор регрессий между версиями движка;
- **`ev.py test` — 102 контрольных примера** на ст. 114 и 115: ставки и
  коэффициенты, порядок конвейера, порог 500/5% на двух годах, фонд ремонта с
  распределением, выбытие по 114.6/114.7/114.9, разбор ввода, откат записи и
  защита закрытого года. Стандартный `unittest`, ничего доустанавливать не
  нужно;
- **changelog и авто-бэкапы** на каждое изменение.

## Формат данных

TSV с табуляцией, **UTF-8 с BOM** (без BOM Excel и Блокнот на Windows ломают
`ə ç ş ğ ı ö ü`), даты ISO, суммы через `decimal.Decimal` — никогда `float`.

```
clients/<клиент>/
   config.toml            идентификация, версия формата
   assets.tsv             карточки ОС — факт поступления
   opening_balances.tsv   входное сальдо (append-only)
   disposals.tsv          выбытия
   repairs.tsv            ремонт (ст. 115)
   additions.tsv          дооборудование
   taxpayer_status.tsv    статус предпринимателя по годам
   rate_elections.tsv     выбранные ставки
   writeoffs.tsv          решения о списании по порогу
   changelog.tsv          аудит-след
```

Плюс `rates.tsv` и `coefficients.tsv` **в корне установки** — правки норм по
годам, один комплект на все клиентские папки: закон одинаков для всех.

## Чего ещё нет

- **QMA (нематериальные активы)** и категория `it` — этап 1d;
- **перенос неиспользованного вычета** — 114.4 абз. 2 и 115.1 абз. 2 дают
  банк на будущие годы, движок его не ведёт;
- **лимит ремонта для `yt`** не выводится из текста: 115.1 не называет
  114.3.2-1. Стоят 3% как допущение;
- **редакция кодекса не сверена с действующей** — `docs/qanun.md` содержит
  текст, из которого взяты нормы, вместе с датой извлечения.

Полный список — CLAUDE.md §12.

## Оговорка

Инструмент считает цифры для налоговой декларации. Ответственность за
поданную отчётность несёт налогоплательщик. Перед сдачей сверяйтесь с
действующей редакцией кодекса и проверяйте открытые вопросы из §12.
